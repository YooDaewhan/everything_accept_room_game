# WSE Survivors 전투 테스트 버전

1~2명이 초대 코드로 같은 방에 들어갑니다. 방장은 방을 만들 때 맵과 난이도를 고정하며, 기본 난이도는 쉬움입니다. 대기실에서 각자 캐릭터와 공격·방어·지원·덤 역할군을 선택한 뒤 방장이 전투를 시작합니다. 근접 캐릭터의 기본 공격은 마우스 방향의 근접 범위, 원거리 캐릭터의 기본 공격은 마우스 방향의 탄환입니다. 전투는 브라우저 영역 전체를 사용하며 왼쪽 위에 체력·경험치 바와 레벨, 왼쪽 아래에 6칸 무기 인벤토리, 위쪽 가운데에 생존 시간, 오른쪽 위에 처치 수를 표시합니다. `전체 화면` 버튼으로 브라우저 전체 화면 모드도 열 수 있습니다. WASD/방향키로 이동합니다. 전장은 2400×1600이며 카메라가 플레이어를 따라갑니다.

몬스터는 다수의 근접형(경험치 5), 소수의 원거리형(10), 드문 돌진형(25)으로 구성하며 종류별 체력·속도·피해가 다릅니다. 몬스터 구성은 맵별 설정 파일에서 바꿀 수 있습니다. 불·물·번개 속성은 각각 화상·동상·마비를 적용하며, 몬스터 종류별 속성 피해 보정이 있습니다. 레벨업마다 무작위 강화 3개 중 하나를 고르고 기존 강화를 다시 골라 레벨을 올릴 수 있습니다. 무기는 공전구·기본 공격·이동 궤적·자동 공격 장치·메테오·둔화 영역·도탄·대포 8종입니다. 무기는 최대 6개 보유하고 각각 LV10까지 강화할 수 있습니다. 처음 LV1로 획득할 때 F/T 타입을 고르며, 시작 무기인 기본 공격도 전투 시작 직후 고릅니다. 선택 중 무적이며 선택 뒤에도 3초간 무적입니다. 대기실과 전투 화면의 무기 도감에서 8종의 타입별 LV1~10 능력치를 볼 수 있습니다. 패시브는 체력·이동 속도·공격 속도·공격력·방어력, 특수 강화는 획득 범위·시야 범위·경험치 증가·추가 이동 속도·주기적 무적입니다. 조합 레시피는 `apps/server/src/systems/Progression.ts`의 빈 목록에 나중에 추가합니다. 실제 드롭 아이템 종류가 아직 정해지지 않아 덤 역할군의 아이템 드롭률 보너스는 후속 아이템 드롭 시스템에서 연결해야 합니다. 보스·승리 조건도 추후 추가 예정입니다.

Node.js 22 이상에서 `npm install` 후 `npm run dev`를 실행하고 http://localhost:5173 을 엽니다. 닉네임을 입력하고 새 방을 만들면 코드와 준비 화면이 바로 나타납니다. 준비 화면에서 방장이 제목·비밀번호와 서바이버즈의 맵·난이도를 설정할 수 있습니다. 운영 환경에서는 두 플레이어가 모두 https://everygame.wsestudio.net 에 접속해야 합니다. 브라우저의 게임 서버 연결은 같은 도메인의 `/gs/` 프록시를 사용하며, 개인 IP나 2567 포트로 직접 접속하지 않습니다. 로컬 서버 health check는 http://localhost:2567/health 입니다. 배포 절차는 `deploy.sh`와 `docs/주의사항.md`를 참고하세요.

- `npm run typecheck`: 전체 타입 검사
- `npm run build`: 전체 프로덕션 빌드
- `npm test`: 서버 이동·중복 처치·레벨업·진화·몬스터 종류 테스트
- `npm run dev:client`, `npm run dev:server`: 개별 실행

환경 변수 예시는 각 앱의 `.env.example`을 참고하세요. React/Vite/TypeScript는 UI와 빌드, Phaser 4는 게임 캔버스, Colyseus 및 SDK/Schema는 방 동기화, tsx는 서버 개발 실행, concurrently는 동시 실행, dotenv는 환경 변수 로드에 사용합니다. 클라이언트는 이동 방향만 보내고 좌표·체력·공격·경험치는 서버가 결정합니다.
